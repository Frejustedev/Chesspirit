# Journal des décisions

Format : date — décision — alternatives écartées — raison.

## 2026-09-27

- **Dépôt vide au démarrage** — Création du projet dans le dépôt `Frejustedev/Chesspirit`, sur la branche de travail imposée par l'environnement `claude/chesspirit-project-g1mur7` ; PR vers `main` à la fin. — Travailler sur `main` directement. — L'environnement impose la branche ; le brief prévoit ce cas.
- **Dossier de projet** — Le PDF fourni est versionné dans `docs/` et ses précisions (arborescence en 8 menus, émissions, villes du Tour, etc.) sont ajoutées à `docs/SPEC.md`. — Ignorer le PDF. — Il complète le brief sans le contredire.
- **Outils disponibles** — Node 22, pnpm 10, Python 3.12 (via uv), Postgres 16 (binaires natifs), Docker (démon démarrable) ; en revanche les registres d'images (Docker Hub, public.ecr.aws) sont bloqués par la politique réseau de la session : `supabase start` est impossible ici. — Abandonner les tests d'intégration. — Voir décision suivante.
- **Pile Supabase locale sans Docker** — `scripts/local-stack.sh` lance les composants open source de Supabase en natif : Postgres 16, PostgREST et GoTrue (binaires officiels des releases GitHub), plus une petite passerelle Node qui expose les chemins `/rest/v1` et `/auth/v1` comme Kong. Le schéma `auth` minimal et les rôles `anon`, `authenticated`, `service_role` sont créés comme dans Supabase. Realtime et Storage ne tournent pas en local : le client bascule sur du rafraîchissement périodique et un stockage sur disque via un adaptateur. Les migrations restent 100 % compatibles avec `supabase db push`. — Base en mémoire factice (ne teste pas la RLS) ; Postgres seul sans API (oblige à dupliquer l'accès aux données). — Permet de tester la vraie RLS et le vrai client supabase-js dans cet environnement ; sur une machine avec Docker, `supabase start` reste l'option standard documentée dans le README.
- **TypeScript 5.9** — TypeScript 7 (réécriture native) est sorti mais l'écosystème (typescript-eslint, Next) n'est pas encore aligné. — TS 7. — Stabilité ; montée de version simple plus tard.
- **Polices auto-hébergées (@fontsource)** — Les polices Google sont empaquetées via npm au lieu de next/font/google. — next/font/google. — L'hôte de polices Google est bloqué dans cet environnement ; l'auto-hébergement évite aussi tout appel tiers (confidentialité, CSP stricte, réseaux lents).
- **Échiquier maison** — Composant d'échiquier écrit sur mesure (grille CSS, pièces SVG maison, jeu au toucher, accessibilité clavier/lecteur d'écran) au lieu de react-chessboard. — react-chessboard (MIT). — Le brief exige des pièces dessinées sur mesure et une interface tactile sobre ; le composant maison est léger et sans dépendance.
- **Chemins en français pour les deux langues** — `/competitions/…`, `/en/competitions/…`. — Chemins traduits. — Public majoritairement francophone ; évite une table de correspondance à maintenir. Le français est servi sans préfixe.
- **Profil = personne, compte facultatif** — `profiles.user_id` est nullable : profils pré-créés (import), enfants gérés, comptes express. La réclamation se fait par le numéro vérifié par code SMS. — Profil lié 1-1 à `auth.users`. — Répond au brief (profils revendicables, compte famille).
- **Écritures sensibles par fonctions SQL** — Inscription, pointage, import du classement, onboarding, confirmation de paiement passent par des fonctions `SECURITY DEFINER` qui vérifient les droits et verrouillent les lignes (capacité). — Logique en TypeScript avec le rôle service. — Atomicité, et la RLS reste la seule source de vérité des droits.
- **Vues publiques** — `public_profiles`, `public_registrations`, `public_standings`, `public_pairings`, `public_ratings` n'exposent que des colonnes non sensibles ; les mineurs apparaissent sous la forme « Prénom I. ». — Politiques par colonne. — Plus simple à auditer ; le conseiller Supabase peut signaler ces vues « security definer », c'est volontaire et documenté.
- **Double authentification dans la RLS** — `private.is_admin()` exige `aal2` dans le jeton : un administrateur sans second facteur n'a aucun droit étendu, même via l'API. — Contrôle seulement dans l'interface. — Défense en profondeur. Désactivable uniquement par le paramètre `require_admin_mfa` (super-administrateur).
- **Paiement confirmé uniquement par webhook signé** — Fournisseur factice compris : sa page de test envoie un webhook signé HMAC au même point d'entrée que FedaPay. Le fournisseur factice est refusé en production sauf `ALLOW_FAKE_PAYMENTS=true`. — Confirmation au retour du navigateur. — Règle métier du brief.
- **Frais « À confirmer »** — Tant que les frais d'un tournoi ne sont pas fixés, l'inscription réserve la place avec paiement sur place. — Bloquer les inscriptions. — Permet d'ouvrir les inscriptions du 3 octobre dès maintenant sans inventer de montant.
- **Heure du 3 octobre inconnue** — Le tournoi est daté du 3 octobre à 00 h 00 (Porto-Novo), horaires « À confirmer » ; le compte à rebours vise le jour J. — Heure inventée. — Pas d'information inventée.
- **Départages et byes** — Règlement FIDE des départages 2023 : les rondes non jouées comptent pour le score, valent le score propre du joueur pour le Buchholz (adversaire virtuel) et n'entrent pas dans le Sonneborn-Berger. — Ancienne règle de l'adversaire virtuel. — Norme en vigueur.
- **Fréquence d'envoi des codes SMS en local** — 5 s par numéro en local (tests), valeur par défaut de Supabase (60 s) en production. — Même valeur partout. — Tests rapides sans affaiblir la production.
- **bbpPairings v6.0.0** — Compilé dans l'image Docker du service Python (Apache 2.0). — JaVaFo. — Moteur homologué FIDE demandé par le brief, licence permissive.
- **Hébergeur du service Python : Fly.io par défaut** — `fly.toml` et workflow prêts, `render.yaml` en alternative. — Railway. — Déploiement Docker simple, mise en veille automatique ; choix final au propriétaire.
- **Tags Git non poussés** — Le proxy Git de l'environnement refuse la création de tags distants (403) : les tags `v0.x` sont créés localement et listés dans le rapport final pour être poussés par le propriétaire. — Contourner le proxy. — Interdit ; à faire en une commande (`git push origin --tags`).
- **Boutique : commande avec compte** — La commande exige une connexion (code SMS, sans mot de passe) ; le panier reste dans le navigateur jusque-là. — Commande invitée. — Rattache le suivi, les points de fidélité et les avis au client ; la connexion par SMS reste rapide.
- **Boutique : calculs en base** — `place_order` recalcule prix, remise, livraison, carte cadeau et points depuis la base et réserve le stock ; `private.order_paid` (appelée par le webhook signé) valide la commande, crédite les points, compte le code promo et émet les cartes cadeaux. Stock restitué à l'annulation ou à l'expiration (`private.expire_orders`, tâche planifiée en phase 2). — Calcul côté navigateur. — Le montant ne doit jamais venir du client.
- **Boutique : tarifs de livraison et fidélité** — Valeurs de démonstration modifiables dans `app_settings` (1 500 F Cotonou, 10 000 F sous-région, gratuité dès 50 000 F, 1 point par 100 F, 1 point = 1 F), marquées « à confirmer ». Adresse du point de retrait « À confirmer ». — Valeurs présentées comme réelles. — Aucune information inventée présentée comme réelle.
- **Boutique : illustrations au lieu de photos** — Les produits de démonstration sont illustrés par des dessins SVG maison ; un champ « Image (URL) » permet d'ajouter les vraies photos. — Photos de banque d'images. — Pas de visuels trompeurs.
- **Location et commandes groupées sur devis** — Formulaire de devis partagé avec le coaching (`quote_requests`, types `rental` et `group_order`). — Catalogue de location. — Tarifs non connus.
- **Suspension de compte** — Profil marqué `suspended_at` et compte bloqué dans l'authentification (`ban_duration`) ; l'application traite un profil suspendu comme déconnecté. Le jeton déjà émis reste valable au plus jusqu'à son expiration (1 h). — Suppression du compte. — Réversible, conserve l'historique.
- **Effacement RGPD par anonymisation** — Identité, coordonnées, consentements et liste de souhaits supprimés, compte de connexion supprimé ; les résultats restent sous « Joueur anonyme » pour ne pas fausser les classements et cotes des autres joueurs. — Suppression en cascade. — Intégrité sportive ; pratique courante des fédérations. À valider dans la politique de confidentialité.
- **Fusion de doublons générique** — `admin_merge_profiles` reporte toutes les clés étrangères vers `profiles` (découvertes dans le catalogue) ; les conflits d'unicité suppriment la ligne du doublon ; cotes recalculées ensuite. — Liste de tables codée en dur. — Les futures tables sont couvertes automatiquement.
- **Remboursements enregistrés, pas exécutés** — Le reversement se fait dans le tableau de bord du prestataire ; l'administration l'enregistre (montant, motif) et met à jour paiement, commande ou inscription. — Appel API de remboursement. — Aucune clé réelle disponible ; à brancher avec les comptes FedaPay/KKiaPay (voir « À reprendre »).
- **Ligues : une journée = un tournoi** — Chaque journée de ligue est un tournoi rattaché (`league_id`) créé depuis l'administration (membres actifs inscrits d'office) ; le classement de ligue additionne points et Sonneborn-Berger de ses journées (vue `league_standings`). — Moteur de ligue séparé. — Réutilise tout le module tournois (appariements, saisie, direct, PDF, cotes).
- **Saison 2026-2027 « en préparation »** — Les 9 championnats et les 6 villes pressenties du Tour (dossier de projet) sont créés sans dates ni montant de licence : affichés « À confirmer ». Une saison de démonstration fictive montre une ligue jouée. — Calendrier inventé. — Aucune information inventée.
- **Tour : barème et coefficients en base** — `scoring_scales` (barème du dossier par défaut), coefficient par étape (Majeure 1,5, en ligne 0,5), nombre de résultats retenus et places des Masters par saison ; points recalculés à la clôture du tournoi lié. — Valeurs codées en dur. — Règle du brief.
- **Lichess : identité seule** — OAuth avec PKCE (sans secret client) ; le jeton est révoqué juste après la lecture de l'identité, seul le nom d'utilisateur est conservé. Création d'Arena possible avec un jeton du compte Chesspirit (`LICHESS_API_TOKEN`, facultatif). Mode factice local (`LICHESS_FAKE=true`) pour les tests. — Conserver le jeton des joueurs. — Minimisation des données.
- **Cote en ligne distincte** — Les tournois en ligne sont exclus des cotes en présentiel ; la cote « online » est rejouée séparément (mêmes règles Elo, sans amorçage FIDE). Les parties Lichess importées forment une ronde unique d'appariements. — Mélanger les cotes. — Règle du brief.
- **Équipes : exempt** — Une équipe exempte reçoit 2 points de match et la moitié des points de partie. Couleurs : l'équipe citée en premier a les Blancs aux échiquiers impairs. Appariement suisse maison (ordre du classement, sans rencontre répétée). — Algorithme FIDE complet pour équipes. — Suffisant pour les interclubs visés ; paramétrable plus tard.
- **Suisse accéléré : méthode Baku (FIDE C.04.5.1)** — Points virtuels transmis à bbpPairings par lignes TRF `XXA` (et ajoutés au repli TypeScript) ; ils ne comptent jamais au classement. — Pas d'accélération. — Vérifié avec le binaire bbpPairings.
- **Annuaire : publication après modération** — Structures proposées et offres d'emploi sont masquées jusqu'à validation ; le proposant devient gestionnaire de la fiche ; revendication d'une fiche existante validée par un administrateur (badge « vérifié »). Les badges ne sont jamais attribuables par l'intéressé (déclencheurs de garde). — Publication directe. — Qualité de l'annuaire et lutte contre les fiches usurpées.
- **Carte : Leaflet et tuiles OpenStreetMap** — Chargée seulement dans le navigateur ; position exacte si fournie, sinon centre-ville approximatif (table de villes du Bénin) signalé comme tel. — Service de cartes payant. — Aucun compte requis ; pour un trafic important, passer à un fournisseur de tuiles (voir docs/LICENCES.md).
- **Mineurs dans la vue publique** — La vue `public_profiles` réduit aussi le nom de famille et la recherche des mineurs (seul `display_name` l'était). — — Protection renforcée des mineurs (brief § 8.8).
- **Politiques des structures** — Les politiques `organizations` / `organization_members` se référençaient mutuellement (récursion détectée par les tests) ; remplacées par des fonctions `SECURITY DEFINER` (`org_is_public`, `org_member`, `org_manager`). — — Correctif.
- **Lexique en fon : jamais inventé** — Le glossaire est livré en français et en anglais ; la colonne fon est vide et se remplit par des propositions de la communauté validées par la rédaction (avec un locuteur). — Traduction automatique. — Aucune information inventée ; le fon n'est affiché qu'une fois validé.
- **Émissions du dossier, sans épisode réel** — Les 5 émissions nommées dans le dossier sont créées ; aucun épisode réel n'existant, un seul épisode de démonstration (sans vidéo) montre le rendu. Vidéos intégrées uniquement depuis YouTube (sans cookies) ou Vimeo. — Vidéos d'autres chaînes. — Contenu non trompeur, CSP restreinte.
- **Leçons et puzzles originaux** — Quatre leçons d'initiation rédigées pour Chesspirit et onze motifs de mat classiques, chacun vérifié automatiquement (chess.js). Tout nouveau puzzle est vérifié à l'enregistrement. — Import de bases tierces. — Qualité et droits maîtrisés.
- **Brouillon d'article à la clôture** — La clôture d'un tournoi crée un brouillon (podium, lien vers les résultats) que la rédaction complète et publie. — Publication automatique. — Validation humaine.
- **Contenu premium** — Marqué et verrouillé à l'affichage en attendant le module d'adhésion (phase 3), qui protégera aussi le texte côté base. — — Phase 3.
- **Tâches planifiées par routes protégées** — `/api/cron/<tâche>` exige `Authorization: Bearer CRON_SECRET` (comparaison à temps constant) ; planification dans `apps/web/vercel.json` (Vercel Cron), transposable à tout planificateur. Chaque exécution est journalisée (`job_runs`). Tâches : expiration des commandes (horaire), rappels J-1 (quotidien), majorité des mineurs, synthèse des alertes, liste mensuelle des cotes (le 1er), import FIDE (le 3), rapport mensuel. — pg_cron. — Visible, testable, indépendant de l'hébergeur de la base.
- **Import FIDE en flux** — Le service Python télécharge la liste officielle (XML zippé), la lit en flux avec `defusedxml` et ne garde que la fédération BEN et les identifiants FIDE connus ; les cotes sont ensuite recalculées. Un fichier local n'est accepté qu'avec `FIDE_ALLOW_FILE=1`. — Téléchargement manuel. — Automatisé et sûr (XML non fiable).
- **WhatsApp derrière un indicateur** — Canal utilisé seulement si la fonctionnalité `whatsapp_notifications` est activée et que la personne l'a choisi (à la place du SMS) ; messages hors fenêtre de 24 h par modèles approuvés (`tournament_reminder`, `booking_reminder`, à créer dans WhatsApp Business). — Envoi systématique. — Coût et consentement.
- **Arbitrage hors ligne** — Page dédiée `/arbitrage/<tournoi>` : copie des deux dernières rondes dans IndexedDB, file des résultats saisis sans réseau, envoi automatique au retour du réseau ; service worker limité à cette page (aucune donnée personnelle dans son cache). — Application hors ligne complète. — Couvre le besoin terrain (coupures pendant une ronde) sans complexifier le reste du site.
- **Statistiques agrégées** — `admin_stats` ne renvoie que des agrégats (aucune donnée nominative) ; export CSV ; alertes sur l'accueil de l'administration et par e-mail quotidien. — Outil d'analyse externe. — Données personnelles minimisées.
