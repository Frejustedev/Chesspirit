# Journal des décisions

Format : date — décision — alternatives écartées — raison.

## 2026-09-27

- **Dépôt vide au démarrage** — Création du projet dans le dépôt `Frejustedev/Chesspirit`, sur la branche de travail imposée par l'environnement `claude/chesspirit-project-g1mur7` ; PR vers `main` à la fin. — Travailler sur `main` directement. — L'environnement impose la branche ; le brief prévoit ce cas.
- **Dossier de projet** — Le PDF fourni est versionné dans `docs/` et ses précisions (arborescence en 8 menus, émissions, villes du Tour, etc.) sont ajoutées à `docs/SPEC.md`. — Ignorer le PDF. — Il complète le brief sans le contredire.
- **Outils disponibles** — Node 22, pnpm 10, Python 3.12 (via uv), Postgres 16 (binaires natifs), Docker (démon démarrable) ; en revanche les registres d'images (Docker Hub, public.ecr.aws) sont bloqués par la politique réseau de la session : `supabase start` est impossible ici. — Abandonner les tests d'intégration. — Voir décision suivante.
- **Pile Supabase locale sans Docker** — `scripts/local-stack.sh` lance les composants open source de Supabase en natif : Postgres 16, PostgREST et GoTrue (binaires officiels des releases GitHub), plus une petite passerelle Node qui expose les chemins `/rest/v1` et `/auth/v1` comme Kong. Le schéma `auth` minimal et les rôles `anon`, `authenticated`, `service_role` sont créés comme dans Supabase. Realtime et Storage ne tournent pas en local : le client bascule sur du rafraîchissement périodique et un stockage sur disque via un adaptateur. Les migrations restent 100 % compatibles avec `supabase db push`. — Base en mémoire factice (ne teste pas la RLS) ; Postgres seul sans API (oblige à dupliquer l'accès aux données). — Permet de tester la vraie RLS et le vrai client supabase-js dans cet environnement ; sur une machine avec Docker, `supabase start` reste l'option standard documentée dans le README.
- **TypeScript 5.9** — TypeScript 7 (réécriture native) est sorti mais l'écosystème (typescript-eslint, Next) n'est pas encore aligné. — TS 7. — Stabilité ; montée de version simple plus tard.
- **Polices auto-hébergées (@fontsource)** — Les polices Google sont empaquetées via npm au lieu de next/font/google. — next/font/google. — L'hôte de polices Google est bloqué dans cet environnement ; l'auto-hébergement évite aussi tout appel tiers (confidentialité, CSP stricte, réseaux lents).
- **Échiquier maison** — Composant d'échiquier écrit sur mesure (grille CSS, pièces SVG maison, jeu au toucher, accessibilité clavier/lecteur d'écran) au lieu de react-chessboard. — react-chessboard (MIT). — Le brief exige des pièces dessinées sur mesure et une interface tactile sobre ; le composant maison est léger et sans dépendance.
- **Chemins en français pour les deux langues** — `/competitions/…`, `/en/competitions/…`. — Chemins traduits. — Public majoritairement francophone ; évite une table de correspondance à maintenir. Le français est servi sans préfixe.
- **Profil = personne, compte facultatif** — `profiles.user_id` est nullable : profils pré-créés (import), enfants gérés, comptes express. La réclamation se fait par le numéro vérifié par code SMS. — Profil lié 1-1 à `auth.users`. — Répond au brief (profils revendicables, compte famille).
- **Écritures sensibles par fonctions SQL** — Inscription, pointage, import du classement, onboarding, confirmation de paiement passent par des fonctions `SECURITY DEFINER` qui vérifient les droits et verrouillent les lignes (capacité). — Logique en TypeScript avec le rôle service. — Atomicité, et la RLS reste la seule source de vérité des droits.
- **Vues publiques** — `public_profiles`, `public_registrations`, `public_standings`, `public_pairings`, `public_ratings` n'exposent que des colonnes non sensibles ; les mineurs apparaissent sous la forme « Prénom I. ». — Politiques par colonne. — Plus simple à auditer ; le conseiller Supabase peut signaler ces vues « security definer », c'est volontaire et documenté.
- **Double authentification dans la RLS** — `private.is_admin()` exige `aal2` dans le jeton : un administrateur sans second facteur n'a aucun droit étendu, même via l'API. — Contrôle seulement dans l'interface. — Défense en profondeur. Désactivable uniquement par le paramètre `require_admin_mfa` (super-administrateur).
- **Paiement confirmé uniquement par webhook signé** — Fournisseur factice compris : sa page de test envoie un webhook signé HMAC au même point d'entrée que FedaPay. Le fournisseur factice est refusé en production sauf `ALLOW_FAKE_PAYMENTS=true`. — Confirmation au retour du navigateur. — Règle métier du brief.
- **Frais « À confirmer »** — Tant que les frais d'un tournoi ne sont pas fixés, l'inscription réserve la place avec paiement sur place. — Bloquer les inscriptions. — Permet d'ouvrir les inscriptions du 3 octobre dès maintenant sans inventer de montant.
- **Heure du 3 octobre inconnue** — Le tournoi est daté du 3 octobre à 00 h 00 (Porto-Novo), horaires « À confirmer » ; le compte à rebours vise le jour J. — Heure inventée. — Pas d'information inventée.
- **Départages et byes** — Règlement FIDE des départages 2023 : les rondes non jouées comptent pour le score, valent le score propre du joueur pour le Buchholz (adversaire virtuel) et n'entrent pas dans le Sonneborn-Berger. — Ancienne règle de l'adversaire virtuel. — Norme en vigueur.
- **Fréquence d'envoi des codes SMS en local** — 5 s par numéro en local (tests), valeur par défaut de Supabase (60 s) en production. — Même valeur partout. — Tests rapides sans affaiblir la production.
- **bbpPairings v6.0.0** — Compilé dans l'image Docker du service Python (Apache 2.0). — JaVaFo. — Moteur homologué FIDE demandé par le brief, licence permissive.
- **Hébergeur du service Python : Fly.io par défaut** — `fly.toml` et workflow prêts, `render.yaml` en alternative. — Railway. — Déploiement Docker simple, mise en veille automatique ; choix final au propriétaire.
- **Tags Git non poussés** — Le proxy Git de l'environnement refuse la création de tags distants (403) : les tags `v0.x` sont créés localement et listés dans le rapport final pour être poussés par le propriétaire. — Contourner le proxy. — Interdit ; à faire en une commande (`git push origin --tags`).
- **Boutique : commande avec compte** — La commande exige une connexion (code SMS, sans mot de passe) ; le panier reste dans le navigateur jusque-là. — Commande invitée. — Rattache le suivi, les points de fidélité et les avis au client ; la connexion par SMS reste rapide.
- **Boutique : calculs en base** — `place_order` recalcule prix, remise, livraison, carte cadeau et points depuis la base et réserve le stock ; `private.order_paid` (appelée par le webhook signé) valide la commande, crédite les points, compte le code promo et émet les cartes cadeaux. Stock restitué à l'annulation ou à l'expiration (`private.expire_orders`, tâche planifiée en phase 2). — Calcul côté navigateur. — Le montant ne doit jamais venir du client.
- **Boutique : tarifs de livraison et fidélité** — Valeurs de démonstration modifiables dans `app_settings` (1 500 F Cotonou, 10 000 F sous-région, gratuité dès 50 000 F, 1 point par 100 F, 1 point = 1 F), marquées « à confirmer ». Adresse du point de retrait « À confirmer ». — Valeurs présentées comme réelles. — Aucune information inventée présentée comme réelle.
- **Boutique : illustrations au lieu de photos** — Les produits de démonstration sont illustrés par des dessins SVG maison ; un champ « Image (URL) » permet d'ajouter les vraies photos. — Photos de banque d'images. — Pas de visuels trompeurs.
- **Location et commandes groupées sur devis** — Formulaire de devis partagé avec le coaching (`quote_requests`, types `rental` et `group_order`). — Catalogue de location. — Tarifs non connus.
